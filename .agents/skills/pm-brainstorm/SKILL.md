# pm-brainstorm

Read [shared Codex workflow conventions](../../WORKFLOWS.md) before using this skill.

Read product vision/status, relevant implemented modules, existing ideas, and finance
rules when money outcomes are involved. Start from the user's pain and pyramid role;
do not mistake ingestion plumbing for the whole product.

Modes:
- analyze: idea in one sentence, pain/persona/frequency/workaround, current competitive
  approaches with verified sources, MVP versus later scope, risks, and fit score.
  Score user value, strategic fit, feasibility, and differentiation 1–5 (20 total);
  explain judgment instead of treating a score as empirical proof.
- compete: verify current competitors; compare segment, behavior, strengths/limits,
  pricing/revenue model where sourced, gaps, and strategic options.
- prioritize: compare candidate features using stated value/effort/risk/dependencies;
  recommend an order and why it fits the current project phase.
- alternatives: offer meaningfully different framings of the same pain, each with
  benefits, costs, assumptions, and a small validation experiment.

Conclude Go / No-Go / Go with scope cut (or missing prerequisites), decisive reason,
and what evidence would change it. Financial soundness, risk enforcement, and legal
exposure are independent of popularity; route to cio/risk-officer/compliance as needed.

For a substantive verdict, save a dated note under docs/codex/ideas/ with sources,
assumptions, score, and decision; preserve prior captures rather than overwrite them.
Do not create GitHub issues, implementation plans, or code automatically. Use
braindump for capture-only requests.
