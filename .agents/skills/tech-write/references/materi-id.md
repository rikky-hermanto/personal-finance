# Materi belajar: progressive learning

Read the mentor skill's current learning-plan and versi-ID sections; preserve its
established curriculum and writing preferences. Shared plans, companions, and glossary
extensions belong beside the relevant plan in `plans/<status>/learning/`; update them directly when requested.

Use these exact section headings in order, without Level X labels:

1. Apa Masalah yang Ingin Diselesaikan?
2. Konsep Sederhananya
3. Cara Kerjanya
4. Implementasi
5. Optimisasi
6. Best Practice
7. Kesalahan Umum
8. Summary

Teach before building. Open with a concrete pain, then a naive approach and the real
limitation that forces the next concept. Earn jargon after its motivation. Each rung
must explain why the previous one was insufficient; avoid a catalog of unrelated terms.

Use one idea per sentence, at most two information units. Finish an analogy in its
own world over 2–3 sentences, then map it to the technical term. Do not interrupt
an analogy with English terms in parentheses. Use natural, consistent Indonesian
classroom prose, avoiding literal English syntax and repeated stock transitions.
Reread each paragraph: if it needs two readings, rewrite it.

Implementasi includes affected files and load-bearing excerpts; link full steps/tests
instead of duplicating the whole plan. Explain actual tuning decisions in Optimisasi.
Kesalahan Umum records real encountered bugs (symptom → cause → fix), not fabricated
experience. Summary includes problem, implementation, measured results when available,
key learning, interview one-liner, and source-plan link. Never invent metrics.

Use clickable relative links computed from the output location. Link first use of a
domain term per section to a shared glossary anchor. Extend the existing shared glossary, preserving anchors and concurrent edits.
For implementation-plan Python blocks, preserve mentor's immediate C# equivalents,
complete introduction ladder, study references, and knowledge-check requirements.
