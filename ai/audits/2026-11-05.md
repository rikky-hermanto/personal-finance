# Context Engineering Update — 2026-11-05

Anthropic reported removing over 80% of Claude Code's system prompt for newer models with no measurable loss, and named six shifts: judgment over rules, interfaces over examples, progressive disclosure, simple tool descriptions, auto-memory, and rich references. This records what that meant for this repo and how the changes tested.

**Result:** a new session starts with 26% less context, every safety rule still holds on Opus, Sonnet and Haiku, and answers got more accurate.

Backups: branches `backup/pre-context-engineering-2026-11-05` and `backup/pre-context-engineering-2026-11-05-worktree`, both at `2a48a987`.

## Before and after test

13 questions on each of Opus 5.5, Sonnet 5.5 and Haiku 5.5, against the backup and the updated setup, with read-only tools in throwaway worktrees. Fable 5.1 was not tested: the account needs usage credits for it.

| Group | Before | After |
|---|---|---|
| Safety rules (money, owner, contract, protected files, risk screens, migrations, fetch) | 21/21 | 21/21 |
| Kept product facts | 3/3 | 3/3 |
| Detail moved out of `CLAUDE.md` | 6/6 | 5/6 |
| Facts that were wrong or missing | 5/9 | 9/9 |
| **Total** | **35/39** | **38/39** |

| Model | Cost before | Cost after | Change |
|---|---|---|---|
| Opus | $6.30 | $5.06 | -20% |
| Sonnet | $2.38 | $1.47 | -38% |
| Haiku | $0.14 | $0.10 | -29% |
| **Total** | **$8.82** | **$6.63** | **-25%** |

Costs are the CLI's reported figures for these runs. The before and after states differ in several ways at once (rules, `CLAUDE.md`, Superpowers), so the saving belongs to the whole update and not to any one change.

- **Starting context:** 66,248 tokens before, 48,887 after, measured on Haiku with MCP servers off.
- **Rule loading:** before, all six rule files loaded in all 39 runs. After, `finance-domain.md` loaded in all 39, and the others only on a matching file: governance 17, frontend 8, backend 6, ai-service 3, docker 0. `paths:` also works on the 2.1.207 CLI that the loop uses.
- **The one miss:** Sonnet named `LlmExtractionClient` rather than `LlmPdfParser` on the routing question. It answered correctly 4 of 4 times on repeat, so this was treated as noise and `CLAUDE.md` was not changed.
- **Scoring limit:** answers were scored by pattern matching, which is coarse. All six protected-file answers were read by hand, and all six warned about the rule. None refused, before or after, so that rule warns rather than blocks.

## Plan style trial

The same small feature was built from two plans, on three models, twice each. Plan A is today's style with full code in the steps. Plan B gives acceptance criteria and pointers to real code, with no pre-written code. A hidden 12-test suite scored the results, and the reference solution passed it first.

| Model | Plan A cost | Plan B cost | Plan A hidden tests | Plan B hidden tests |
|---|---|---|---|---|
| Opus | $0.81 | $0.90 | 24/24 | 24/24 |
| Sonnet | $0.25 | $0.26 | 24/24 | 24/24 |
| Haiku | $0.02 | $0.02 | 24/24 | 24/24 |

Costs are per run; test counts cover both repeats.

- Plan B matched Plan A on correctness on every model, with a plan half the size (1.9KB against 3.8KB).
- Plan B cost about 10% more to execute overall ($2.36 against $2.15), because the model has to read the references and write the code.
- Every Plan B run applied a Pydantic rule stated only in `ai-service.md`, so scoped rules do reach the model.
- **Limit:** this was one small, single-module task. The cost of writing the plan was not measured, and that is where Plan B should save the most. It does not show how Plan B behaves on a large multi-file ticket.

The `plan` skill was not changed. Try Plan B on a real medium ticket before deciding.
