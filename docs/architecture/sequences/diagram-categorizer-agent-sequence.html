PF-AI007 — Categorizer Agent (smolagents ToolCallingAgent): ReAct loop sequence

One POST /categorize-agent call — from a raw transaction to a traced, evidence-based category
Caller AI Service CategorizerAgent LLM Tools Retriever / PG Observer

Use case: categorize the transaction "GJ*GRAB CAR JAKARTA" (wallet BCA, 45,000 IDR) — the plan's own worked example. Unlike the silent LLM-fallback layer of the existing 4-layer categorizer, the agent gathers evidence in a visible loop: it calls search_category_rules, sees "No rules matched", calls find_similar_transactions (pgvector, PF-AI003), then list_all_categories to confirm the exact vocabulary name — three tool calls, max_steps=3 reached, final answer synthesized from context with no fourth tool call.

What closes the loop: ToolCallingAgent.run() exits once the LLM replies with plain text instead of a tool call, or max_steps is spent. CategorizerAgent._parse_result extracts CATEGORY/CONFIDENCE/REASONING from that text, and tool_calls_count is read from the agent's own agent.memory.steps — never hardcoded.

⚠️ No frontend or .NET caller wired up yet — POST /categorize-agent is a fully standalone Python endpoint (confirmed in docs/architecture/sequences/diagram-transaction-categorizer-sequence.html's own footer warning), so the "Caller" lane here is scripts/test_agent.py / curl, not a UI. Also: instrument_smolagents() does not exist on the installed smolagents 1.26.0 — the Observer spans shown here are the plan's documented fallback (manual Langfuse as_type="agent" / as_type="tool" spans), live-verified via the Langfuse public API, not the one-line auto-instrumentation the plan originally assumed.
