AI Chat RAG — request/response sequence

Two turns through POST /ask/stream — a numeric ("aggregate") question and a lookup question — plus the transaction-indexing lane that feeds pgvector
User Frontend AI Service Planner/Retrieval Reranker Gemini .NET API Postgres Observer

Use case (view 1): the chat panel talks directly to the Python AI service over SSE — there is no .NET participant in this flow at all. QueryPlanner makes one temperature-0 Gemini call to classify the question as aggregate (a number question, e.g. "berapa total belanja makan bulan ini?") or lookup (a "which transactions..." question), then the two branches diverge sharply: aggregate runs a plain SQL SUM/COUNT and only asks the LLM to narrate a number that is already correct before generation starts (verified:true "by construction"); lookup runs the pgvector similarity search → FlashRank rerank → sends the top-3 contexts to the client before generating, then streams the grounded answer token-by-token.

What closes each branch: the SSE done event always carries verified and confident flags computed independently of the LLM's own claims — aggregate is verified by construction (the number was computed in SQL, not asked of the model); lookup is verified by checking every [n] citation marker the model emitted against the actual context set it was given (main.py:542-547). Any citation to a context that wasn't sent flips verified:false client-side, not silently trusted.

Error / empty-result paths (not drawn in the happy-path lanes above, but real)

• Planner call fails → SSE error event {detail:"planner_failed"}, no answer generated.
• Aggregate with count==0 → metadata(total 0) + done(confident=false) — no LLM call at all.
• Lookup with empty reranked contexts → done(confident=false, contexts:[]) — no LLM call; frontend shows a static "no relevant transactions" fallback.
• stream_generate exception on either branch → SSE error event {detail:"generation_failed"}.
• Frontend's onclose/onerror handlers in chatApi.ts deliberately throw to stop fetch-event-source's silent auto-reconnect — a silent reconnect would silently re-run a paid LLM generation.

⚠️ No multi-turn memory: grep for session_id|trace_id|thread_id in the ai-service chat path returns nothing — unlike the PF-AI008 advisor (which checkpoints state under thread_id), each /ask, /ask/stream, and /ask/followups call is stateless and gets its own independent Langfuse observation. search_mode defaults to vector — hybrid BM25+RRF code exists (retriever.py) but is not the active default (PF-AI006 eval: vector alone scored higher, MRR@5 0.771 vs 0.750).
