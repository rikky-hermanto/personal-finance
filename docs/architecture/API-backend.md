# Backend Architecture

> **Code reviewed:** 2026-10-08. Reference for the current .NET implementation.

## Composition and layers

`apps/api/PersonalFinance.slnx` contains Api, Application, Domain and Infrastructure plus xUnit/Moq tests. Projects target net10.0. Persistence/DbContext/EF migrations have been removed.

- **Api:** controller routes, dependency injection, CORS, exception middleware, OpenAPI and health endpoints.
- **Application:** MediatR commands/handlers, validators, DTOs, service interfaces and Supabase-backed orchestration. Financial Buckets and Desk engines are pure calculation modules.
- **Domain:** PostgREST-mapped entities and events. This layer carries SDK mapping annotations; do not describe it as wholly independent of persistence packages.
- **Infrastructure:** bank signatures/parsers, typed FastAPI HTTP clients, Supabase Storage, FX/valuation/net-worth services.

`Program.cs` registers parsers/signatures, services, typed HTTP clients, MediatR and FluentValidation. Most mutations use handlers; reads and some mutations use services. TransactionsController still contains submission/account-resolution logic and direct Supabase queries. This is the actual topology, not a claim that every controller is thin or every data access goes through a repository abstraction.

## Parsing and categorization

Registered signatures cover BCA CSV, standard CSV, NeoBank PDF and Superbank PDF. Parser keys dispatch BCA, NeoBank, Superbank→LlmPdfParser, standard CSV and generic LLM PDF. Images bypass bank signatures and call the extraction client. There is no dedicated Wise+FX parser or YAML profile registry.

The standard upload endpoint calls the selected parser, account resolution and duplicate tagging. BCA/standard/LLM PDF parsers invoke CategoryRuleService. Full normalization/batch suggestion/residual categorization is a separate service currently used only by experimental upload-preview-new's CSV branch. The PDF/image branch returns a storage processing_id without a completing worker. Superbank's Python-specific prompt is not selected by the normal .NET path because LlmPdfParser passes bankHint:null.

CategoryRuleService preserves an already-set category, then consults exact normalized description/remarks history, user rules and presets. Pipeline residual categorization first tries merchant suggestions then /categorize. The .NET client bounds category/confidence output; automatic residual rule creation also requires rule_seed_allowed. Jev never sets that permission. Preview Suggest uses a different command/client and is unaffected by the Jev toggle.

## Database and contracts

Data access uses Supabase/PostgREST. SQL schema lives in repository-root supabase/migrations; API startup does not apply migrations. The AI service also connects to Supabase Postgres via asyncpg for embeddings/search/aggregates.

TransactionDto has integer Id, DateTime Date, transient AccountName, nullable Guid AccountId, decimal AmountIdr/Balance and nullable decimal ExchangeRate/StatementBalance. DB/CR semantics remain explicit. Python extraction uses account_name; some retrieval models retain wallet as a display label. Existing Python/TS/HTTP numeric contracts still contain float/number conversions; C# decimal does not establish end-to-end decimal serialization.

Successful submission inserts confirmed nonduplicates and starts background embedding with Task.Run. This enrichment is not a durable job queue. Realtime notifications are generated by transaction INSERT publication.

## Security and diagnostics

No JWT authentication registration or user login integration exists. UseAuthorization alone does not establish authenticated tenant isolation. Journey/Desk/Buckets use placeholder identities and many app-table RLS policies allow all access.

CORS permits localhost frontend origins 8080/8081/8082. OpenAPI is development-only. Health probes check a separately configured Npgsql database connection, AI /health and Grafana; the Npgsql probe can point to Compose's standalone database rather than the actual Supabase persistence store.

ILogger is present in DashboardService and SpendingAnalysisService, contrary to older status notes. OTel exports traces/metrics/logs to Alloy. Exception middleware returns generic 500 with DEBUG detail; upload-specific catches can still expose exception messages. Do not claim complete error redaction.

## Development and checks

From repository root:

```powershell
rtk dotnet run --project apps/api/src/PersonalFinance.Api
rtk dotnet build apps/api/PersonalFinance.slnx
rtk dotnet test apps/api/PersonalFinance.slnx
```

xUnit suites cover parsers, clients, commands, categorization, balances, BucketCalculator, Desk calculations/presets/parity fixtures and macro-scenario commands. Several legacy integration tests are skipped for missing Supabase harnesses. No build/test run was performed during this documentation-only audit.
